GSwitch Claude Tool · proposal for v1.16 onward

GSwitch UX Redesign

GSwitch already does a lot: it keeps several Codex accounts, switches between them, and lets Claude Code hand work to Codex or to cheaper Claude models. Today a new user sees the parts but not the whole. This proposal reorganizes the app and both plugins around what a person is trying to do, in words they already know.

Based on a walk-through of every screen in v1.14.0 (demo mode), every on-screen string in the app, the 7 Codex plugin commands and the 4 router commands. Mockup data are examples.

What gets in the way today

Each finding is something a first-time user would hit. Most are about words and placement, not missing features.

First screen

The app opens on a grid of account cards. Nothing says what GSwitch is for or how it connects to Claude Code.

The only setup hint is "Add your Codex accounts". The Claude Code side (plugins, setup choice) is never introduced.

Setup choice

"Claude only / Claude + Codex / Router" are explained in one line each, and the Router line assumes you know what a worker is and what escalating means.

Nothing shows what will actually happen to your next task under each choice, or what it costs.

Settings split

Settings live in two dialogs reached from one button. "Invoke settings..." appears twice in the same panel. Which accounts Codex may use is set on each account card, while their order and reserve are set in the Invoke dialog.

Model names

Choices are raw IDs and effort levels (gpt-6.1-sol, haiku × low…max, up to 30 checkboxes). There is no hint of which is strong, slow or expensive.

What is happening

The app shows running Codex tasks, but not what the router decided, which Claude workers ran, or how well each model did. Those live only in chat (/router:stats, the Router line), in different words.

Plugins

Two plugins, eleven commands, three naming styles. /codex:setup, /codex:invoke-status, /router:mode and the status line all partly answer "is this set up right?".

Router output speaks in internals: "floor 55 (hard)", "candidates", "Next after verify".

Translation

The newest panel text (Use first, Speed, Fast cutoff, Try cheaper models) is written straight into the code, so the Chinese interface shows it in English.

The new shape

Five places, named by what you do there. Everything about one subject lives in one place. Advanced options stay, folded under "Fine-tune" with one line on what each one changes.

Home

One sentence on how your setup works, whether anything needs you, and what is running now.

Accounts

Your Codex accounts, their usage, and in one list which ones Claude may use and in what order.

Claude Code

How Claude and Codex share work. A guided choice with a preview, plus "Fine-tune".

Results

What each model did: tasks, success rate, time, cost. The data captured in 1.15 shows up here.

Settings

Appearance, language, updates, Codex CLI, plugin install check.

Words: what changes

Internal names stay in the code and in logs; people see the plain version. Where a term is the vendor’s own (5-hour limit, reasoning effort), it stays and gets a one-line explanation the first time it appears.

Plugins

The plugins keep working the same way; their output and command names change so chat and the app tell one story.

One check

A single /gswitch:status answers “is everything set up?”: app running, setup choice, plugins, Codex signed in, accounts Claude may use. It replaces the overlap between /codex:setup, /codex:invoke-status and /router:mode (the old names keep working).

Per-message line

“Router: mode=mixed · Use first: codex · Claude 5h: unknown · …” becomes one sentence matching Home, for example “Automatic team · Codex first · Claude plan: 64% left”.

Plan output

“floor 55 (hard)” becomes “Needs a strong model (hard task)”, and each option shows its plain name, cost and time.

Stats

/router:stats prints the same columns as the Results screen and points to it.

Order of work

Phase 1 · app 1.16

Structure and words

  • Five sections with left navigation
  • Home with the setup sentence and Running now
  • One list for which accounts Claude may use, order and reserve
  • All new wording, every string translated
Phase 2 · app 1.17

Guidance and results

  • Guided Claude Code choice with the “typical task” preview
  • Fine-tune with a line per option
  • Results screen from the captured data
  • First-run steps: accounts, setup choice, plugin check
Phase 3 · plugins

Chat matches the app

  • /gswitch:status
  • Plain per-message line and plan output
  • Stats in Results’ columns
  • Old commands kept as aliases

Decisions

Decided by the owner on 2026-10-10.

1. Navigation

Left sidebar with five sections.

2. Renames

The word table is accepted. Internal names stay in code and logs.

3. Chinese translation

Dropped. The language menu and the Chinese text are removed; the app is English only.

4. One status command

Add /gswitch:status; the old commands keep working.
